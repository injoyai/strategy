# Project Memory

## Current baseline

- The repository is a documentation-first strategy research platform; no runnable backend or frontend exists yet.
- Go is the required backend. The proposed UI is React + TypeScript + Vite with Ant Design and ECharts. HTTP uses OpenAPI JSON plus SSE for persistent Job events.
- Domain ports and HTTP DTOs are separate contracts. `docs/contracts/contracts.go` is a proposed extension-port draft, not a persistence model or runnable implementation. `docs/api/openapi.json` is generated by `docs/api/build_openapi.py` and must not be edited directly.

## Architecture invariants

- Research inputs are immutable and versioned: Snapshot, UniverseVersion, FactorVersion, StrategyVersion and model policies. Job lifecycle is separate from Run identity and evidence.
- `DataView` is bound to `snapshot_id + as_of`; PIT selection uses `available_at`, preserves revisions, and must not substitute `ingested_at`. Unknown PIT evidence fails closed in strict mode.
- Forced ingestion always calls the upstream provider and records a new request/batch even when cache is current; identical content may be checksum-deduplicated.
- Strategy code cannot access network, database, filesystem or unmanaged time. Backtests use fixed event ordering and seed. Ledger is the sole writer for cash, positions and equity.
- Unknown market, provider, account, deployment, fee, fill or metric decisions remain explicit blockers; do not create example defaults.

## Delivery plan

- `docs/implementation/` is the executable implementation baseline: M0 persistent Job/synthetic snapshot slice, M1 real data/PIT/universe/factors, M2 deterministic backtest/report/experiment loop, M3 research enhancement, and the design gate that keeps M4 trading integration blocked, plus frontend and verification traceability.
- M0 may proceed without choosing a market, but Go module path/toolchain and at least an M0 deployment assumption must be approved first. M1 requires DEC-01/02/03; M2 requires DEC-05/06 and versioned market/fill/cost/metric policies.
- Acceptance coverage is AC-01..12 and requirement coverage is the 24 IDs listed in `docs/requirements.md`; stage completion requires code, tests, migrations/config, contract/docs and reproducible evidence.
