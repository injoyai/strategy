## Architecture invariants

- Research inputs are immutable and versioned: Snapshot, UniverseVersion, FactorVersion, StrategyVersion and model policies. Job lifecycle is separate from Run identity and evidence.
- `DataView` is bound to `snapshot_id + as_of`; PIT selection uses `available_at`, preserves revisions, and must not substitute `ingested_at` (ReplayTime is only an optional secondary upper bound `ingested_at <= replay_time` for manual replay). The SQL also applies the half-open effective window `effective_from <= ? AND (? < effective_to)` (windowless rows always pass); as_of is pinned at OpenView — changing as_of requires reopening the view. Unknown PIT evidence fails closed in strict mode.
- Data plane conventions (internal/data): `quality_status` vocabulary is `clean`/`info`/`warning`/`error` (worst-severity reduction of the stored Issue list; error short-circuits). Publishing is fail-closed: any error-severity issue → `resource.conflict`, and strict PIT additionally rejects rows with `published_at IS NULL`. List APIs (batches/snapshots) do NOT mint cursors — the server's pagination layer decodes the 24h cursor and hands `Sort`/`AfterID`/`Limit` to the store, which returns the last item's id as `NextCursor` (id-only keyset); `/data/query` cursors are store-minted decimal offsets (safe: pinned snapshot+as_of is immutable). Observations carry denormalized query columns (available_at/revision_id/published_at) beside `provenance_json` as source of truth; PIT filter (`available_at <= as_of`) is applied in SQL BEFORE the latest-revision rule, whose winner is the last row under `ORDER BY instrument_id, event_time, available_at, revision_id, id` (rowid tie-break). Batch checksum = SHA-256 over sorted canonical row JSON; byte-identical rows within one Append collapse (cross-request retry dedup is the idempotency layer's job).
- Forced ingestion always calls the upstream provider and records a new request/batch even when cache is current; identical content may be checksum-deduplicated.
- Strategy code cannot access network, database, filesystem or unmanaged time. Backtests use fixed event ordering and seed. Ledger is the sole writer for cash, positions and equity.
- Unknown market, provider, account, deployment, fee, fill or metric decisions remain explicit blockers; do not create example defaults.

## Contract chain conventions

- `docs/api/openapi.json` is generated by `docs/api/build_openapi.py` and `web/src/api/schema.d.ts` by `npm run gen:api`; both generated artifacts are committed and `scripts\verify.ps1` fails on any uncommitted drift. Never hand-edit them.
- Server routes are registered through `server.API.Handle` with patterns relative to the API root (e.g. `/things`); the `/api/v1` prefix is added automatically and matches the OpenAPI `servers` entry. Unmatched paths under `/api/v1` answer the contract error envelope (404 `resource.not_found`); 405 keeps ServeMux's default text because the spec declares no 405 responses.
- Contract behavior is pinned by `internal/server/contract_test.go`, which walks every operation in openapi.json (45 paths / 50 operations) with stub handlers; adding an operation to the spec automatically adds a test case.
- Error mapping is single-point in `internal/server/errors.go`: validation.*→400, auth.unauthorized→401, auth.forbidden→403, resource.not_found→404, resource.*conflict/idempotency.conflict→409, pagination.cursor_expired→422, rate.limited→429 (retryable), internal.unavailable→503 (retryable), anything else→500 with a fixed "internal error" message (fail-closed).
- Idempotency: required for POST operations declaring the `Idempotency-Key` header (8..128 chars); scope is `caller|workspace|method|path`; replays 24h then re-execute; store is in-memory for M0-03 — M0-04 adds the SQLite `idempotency_records` store plus goose migrations.
- Pagination: `limit` 1..200 (default 50); cursor is a base64url-encoded payload expiring after 24h (422 `pagination.cursor_expired`, strict `>` comparison at the TTL boundary); `sort` is whitelisted per endpoint (`id`/`-id`). An absent/empty `cursor` query param is the canonical first page and must short-circuit in `ParseCursor` — only non-empty malformed cursors answer 400.
- Server dispatch: `internal/server/api.go` Handler() must route through `mux.ServeHTTP(w, r)` (with a miss-check via `mux.Handler(r)` for the error-envelope 404). Manually invoking the handler returned by `mux.Handler(r)` never populates `r.PathValue` for `{id}` routes — the stdlib sets pattern/matches only inside `ServeMux.ServeHTTP`, so every wildcard-route fetch would 404 silently.
- Middleware ResponseWriter wrappers must forward `http.Flusher.Flush()`: `statusRecorder` (access-log) does, and SSE streaming silently deadlocks in net/http's 4KB response buffer without it (server goroutine healthy, client never sees headers).
- Availability policy: `pipeline.applyAvailabilityPolicy` stamps `Provenance.PublishedAt = &AvailableAt` when the upstream announces no publish time (conservative default per the domain.Provenance contract, never the event time) before Append; strict-PIT snapshot publish rejects batches whose observations carry NULL `published_at`, so skipping this makes strict-PIT snapshots unpublishable for such sources.

## Stock screening design scope

- The user scoped stock screening to design documentation only. `docs/stock-screening-design.md` is Proposed; its candidate endpoints, domain objects and SCREEN/SC-AC IDs are not active OpenAPI contracts or implemented features. Implementation must explicitly integrate the contract/client/test chain rather than treating the design examples as current API support.
- The design separates immutable ScreenerVersion rules from point-in-time ScreenRun results, reusing Snapshot/DataView, Universe/Factor, Job and Artifact boundaries. A saved static universe retains selection time and source evidence; it must not be backfilled into earlier backtest decisions. Unknown values use three-valued filtering; ranking membership, missing-value policy and tie-breaking are explicit.

## Historical replay direction

- The user explicitly chose manual historical replay: advance one trading day at a time and decide buys/sells in the UI. `docs/historical-replay-trading-design.md` records the Proposed design; automatic batch backtesting is a separate workflow, and this delivery does not implement replay endpoints or change the active OpenAPI.
- ReplaySession is distinct from Job and automatic Backtest Run. It freezes data/models, constrains all displayed data and screening to the session's historical time, and accepts manual order intents for subsequent-event matching through shared market/fill/cost/ledger components. Daily advancement is an atomic checkpoint transition with revision/idempotency/fencing protection; completed fills cannot be undone by navigating backward. Session end cancels remaining orders and preserves open positions instead of inventing a final-price liquidation.
