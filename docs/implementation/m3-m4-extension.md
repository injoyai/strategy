# M3 研究增强与 M4 交易接入边界

本文补齐需求路线图的后续阶段。M3 在 M2 研究闭环上扩展研究证据；M4 当前只定义启动前必须完成的设计与门禁，不授权实现交易接入。

## 1. M3 研究增强

前置：`GATE-M2-DONE`。新增数据/因子仍分别通过 Provider、Normalizer、Snapshot、Factor 和 Artifact 契约，不绕过 M1 的 PIT、修订、单位与许可规则。

### M3-01 数据包扩展

按策略需求逐包推进，而非一次接入全部目录：

1. 估值研究包：历史股本、valuation、分红及历史口径。
2. 财务研究包：三大报表、公告/修订、单季/累计、主体映射与行业。
3. 增强研究包：资金、融资、持仓、预测、事件、宏观或盘口。

每个包都要补齐能力探针、许可、schema/mapping/availability policy、坏样本、PIT 反例、质量规则、恢复和容量基准。没有历史修订证据的数据标为 `pit_unverified`；不能因为字段存在就宣称相应因子可严格研究。

### M3-02 因子家族扩展

按 [因子与数据源目录](../factor-data-catalog.md) 的依赖实现。每个 FactorVersion 交付：公式与单位、适用资产、输入与 lookback、分母/负值/缺失策略、PIT 规则、参数 schema、分析 label、数值 oracle 和性能基准。

财务流量先将同一口径累计值差分为单季，再构造 TTM；余额不做四季度累加。供应商派生估值与平台重算估值分别命名、保留口径并做样本对照，不覆盖为一个字段。

### M3-03 参数批量与尝试登记

批量任务先生成不可变 ExperimentPlan：基础 Run、参数空间/显式候选、最大组合数、资源估算、seed policy、停止条件和预算。服务端在启动前展开或可验证地分片，保存所有候选身份。

- 每个候选是独立 Run/Job 或有等价持久化生命周期，成功、失败、取消都保留。
- 取消父计划停止未开始候选并请求取消运行中候选，不删除已完成结果。
- 资源/供应商限额在计划级和工作区级执行；不能因页面关闭而失效。
- 排名只比较 MetricPolicy、币种、区间和样本口径兼容的结果，并同时展示尝试总数与失败数。

### M3-04 滚动验证与市场阶段

滚动计划版本化定义训练、验证、测试窗口长度、步长、预热、embargo/间隔（若采用）、拟合与选择规则。每个窗口的预处理只在训练段拟合；验证用于选择；测试集使用历史不可重置。

市场阶段切片由版本化、可复现规则生成，不能看完结果后无记录地重命名区间。成本压力通过明确的 CostModel 版本/参数运行新 Run，不在报告端把指标乘系数伪造。

### M3-05 M3 验收

- AC-11：测试段极值不能影响训练拟合；测试集使用历史永久保留。
- VALID-02：参数扰动、成本压力、市场阶段和滚动验证的全部尝试可追踪。
- 新数据与因子分别通过 PIT/修订/单位/缺失/数值 oracle，不降低 M1 严格模式。
- 批量计划中途重启、取消和部分失败后，候选数量与终态守恒，不重复发布。
- 页面显示数据证据限制、试验总数和样本划分，不只突出最优结果。

## 2. M4 当前状态：Blocked

DEC-04 未批准，且现有正式设计只规定“未来交易接入”和“不得复用研究 Job 生命周期”。因此不得从 ResearchExporter 直接下单，也不得把 Backtest 的 Ledger、FillSimulator 或 JobService 当作真实账户事实源。

[历史手动复盘](m2-manual-replay.md) 使用历史数据和项目内模拟账户，即使功能完成也仍属于研究工具，不是 M4 的实时模拟盘或实盘适配器。ReplaySession、模拟账户或 ManualOrder 不得被转接到券商；若未来复用模型，必须通过下述独立交易设计和准入。

`GATE-M4-START` 前需要新建设计评审，至少回答：

| 主题 | 必须明确的契约与故障场景 |
| --- | --- |
| 范围与准入 | 模拟/实盘、市场/场所、账户类型、监管/许可、启用审批 |
| 账户事实源 | 余额、持仓、订单、成交、资金、公司行为的权威来源与写入所有权 |
| 订单生命周期 | client/order/execution ID、幂等、撤改、部分成交、拒单、乱序/重复事件 |
| 风险 | 下单前/后限额、预留与释放、Kill Switch、未知配置 fail closed |
| 可靠投递 | 事务边界、Outbox/Inbox 或等价机制、断线重连、恢复后不重复外发 |
| 对账恢复 | 券商/场所快照与本地状态对账、差异处理、人工介入、审计证据 |
| 时间与日历 | 场所时钟、交易阶段、超时、时钟漂移、重启期间事件 |
| 安全运维 | secret、最小权限、隔离、日志脱敏、部署、监控、演练和回滚 |
| 研究包兼容 | schema/version/model 映射、许可检查；导入不等于启用交易 |

该评审必须新增交易需求 ID、状态机、接口、威胁模型、故障注入计划、paper 准入和 live 准入验收。只有 paper 环境长时间运行、对账和恢复满足已批准目标后，才能另行决定是否允许 live；本实施文档不设虚构期限或默认阈值。

## 3. 版本与兼容

M3/M4 不得修改已发布 Run 的语义。因子公式、数据可用时间、市场/费用/成交/指标 policy 或研究包 schema 变化均创建新版本；破坏性 HTTP 变化新增 API 主版本。迁移工具可以读取旧版本，但结果必须记录转换版本、损失和 checksum，不能覆盖原 artifact。
